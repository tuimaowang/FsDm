GetScreenData

函数简介： 返回指定区域的 CPU 二进制颜色数据地址，供同进程代码使用。

函数原型：


uintptr_t WINAPI GetScreenData(int x1, int y1, int x2, int y2);

参数定义：

  • x1/y1：区域左上角，客户区物理像素坐标，不能为负数。
  • x2/y2：区域右下角，不包含此边界，要求整个区域有效；不自动裁剪越界区域。

返回值： 非零为区域数据首地址，0 为失败，错误查询同线程 GetFindStatus。 数据没有文件头，从上到下、每行从左到右紧密排列，宽 x2-x1、高 y2-y1， 容量为 宽×高×4。每个整数像素是 00RRGGBB，Windows 小端内存顺序为 B,G,R,0。 最多 16,777,216 个区域像素；客户区尺寸与原始渲染尺寸不同时按比例最近邻取样。

示例（C++ 调用）：


const uintptr_t address = GetScreenData(0, 0, 100, 100);
if (address) {
    const auto* pixels = reinterpret_cast<const uint32_t*>(address);
    const uint32_t firstColor = pixels[0]; // 00RRGGBB
}

注意： 必须使用 uintptr_t 等 64 位类型接收，不可用 Windows 的 32 位 long。 内存属于 DLL，禁止释放；至同线程下一次 GetScreenData（包括失败调用）或该线程退出前有效。 需要跨调用保留时立即复制，其他线程的调用不覆盖本线程地址。 这个地址只在加载 DLL 的目标进程中有效；数据不是完整 BMP 文件，不能直接交给 LoadPicByte。 该函数必需按需读取 CPU，不受找图后端设置影响，不重建设备。 工作台可直接调用并显示十六进制地址，以及采集取帧、区域整理和其他耗时。
