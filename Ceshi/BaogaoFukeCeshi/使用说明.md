# 目标进程内 LuaJIT 测试

本目录新增独立的 LuaJIT 桥接 DLL，供**已经由你授权并选择的测试进程**加载。桥接 DLL 通过 `LoadLibraryExW` 加载 `jiaofu` 目录中的原版 `ZhaoTu.dll`，将找色、找图、窗口 OCR 等函数转给它，并提供当前进程 CPU 时间读数。

**不会修改 `ZhaoTu.dll` 或 `ZhuaTu.dll`，也不提供或启动注入器。** 由你使用自己的方式把桥接 DLL 加载到目标进程，再由目标进程内的 LuaJIT 执行测试脚本。

## 文件说明

- `lua_jiekou_qiaojie.cpp`：独立桥接 DLL 源码；`DllMain` 保持空操作，加载和初始化由脚本显式控制。
- `LuaJiekouQiaojie.vcxproj`：桥接 DLL 的 x64 构建项目。
- `baogao_zhuru_ceshi.lua`：目标进程内执行的 LuaJIT 测试脚本；直接测试绑定窗口，包含找色、找图、OCR 与进程 CPU 统计。
- `baogao_fuke_ceshi.lua` 和 `BaogaoFukeCeshi.vcxproj`：之前创建的独立进程测试入口。要测目标进程本身，请改用桥接 DLL 流程。

## 构建

在 VS Code 打开本目录，运行任务：

**终端 → 运行任务 → 生成 LuaJIT 桥接 DLL（x64 Release）**

或在 Visual Studio 2022 中打开 `LuaJiekouQiaojie.vcxproj`，配置选择 `Release | x64` 后生成。产物为：

```text
bin\qiaojie\x64\Release\LuaJiekouQiaojie.dll
```

目标进程必须是 **64 位**，因为当前 `jiaofu` 的 DLL 为 x64。目标进程还必须有可运行 LuaJIT FFI 脚本的 Lua 环境；仅加载桥接 DLL 不会自动创建 Lua 运行时或自动运行脚本。

## 在目标进程内运行

1. 用你自己的进程加载方式，把 `LuaJiekouQiaojie.dll` 加载到目标测试进程。桥接 DLL 在加载通知中不做初始化。
2. 确认 `FsDm\linshi\jiaofu` 交付目录及其配套依赖仍在原位置；脚本会把该目录作为配置传给桥接 DLL。
3. 在 `baogao_zhuru_ceshi.lua` 的 `default_config()` 中修改 `hwnd`、采集方式、模板目录等参数。`hwnd` 必须是目标进程所拥有的有效窗口句柄。
4. 找图需要模板目录中包含 `主页.bmp` 和 `应用.bmp`。若缺少，脚本会跳过找图。
5. 在**目标进程内的 LuaJIT** 中执行 `baogao_zhuru_ceshi.lua`。可以由目标程序自己的 Lua 控制台/脚本加载器执行，也可以由你现有的进程内 Lua 执行方式调用 `dofile`。
6. 每次运行会重写 `baogao_zhuru_jieguo.txt`，可在 VS Code 中打开查看。

默认桥接 DLL 位于本项目 `bin\qiaojie\x64\Release`，默认模型目录为 `FsDm\third_party\ocr_models`。如果运行目录不同，可在脚本开始前设置全局 `BAOGAO_CESHI_CONFIG` 表来覆盖 `bridge_path`、`jiaofu_dir`、`model_dir`、`template_dir`、`log_path` 等配置。

示例（要在目标进程内执行，不要在普通外部终端单独启动 LuaJIT）：

```lua
BAOGAO_CESHI_CONFIG = {
    hwnd = "0x000A1234",
    display = "wgc",
    find_backend = "cpu",
    ocr_backend = "cpu"
}
dofile([[C:\Users\Administrator\Documents\DaMo\FsDm\Ceshi\BaogaoFukeCeshi\baogao_zhuru_ceshi.lua]])
```

## CPU 指标含义

脚本使用 `GetProcessTimes` 对目标进程测试前后的累计 CPU 时间作差，统计该进程**所有线程**在测试区间消耗的 CPU 时间。因此它包含宿主程序的后台工作，不是某一个 DLL 函数的独占 CPU 时间。

- `进程 CPU`：测试期间目标进程所有线程的累计 CPU 秒数。
- `单核比例`：进程 CPU 秒数 ÷ 墙钟秒数 × 100%；多线程时可能超过 100%。
- `整机比例`：单核比例 ÷ 系统逻辑处理器数。

## LuaJIT FFI 调用示例

桥接 DLL 的公开函数包括 `QjInitialize`、`QjBindWindow`、`QjFindColorEx`、`QjFindPic`、`QjOcr`、`QjFreeResult`、`QjGetProcessCpuTime100ns` 和 `QjShutdown`。找色/找图/OCR 的结果仍由原版 `ZhaoTu.dll` 持有，必须调用 `QjFreeResult` 释放，不能在 Lua 中自行释放其指针。

不要在宿主进程正在执行识别时调用 `QjShutdown`。脚本完成后会先解绑，再请求桥接层释放自己持有的模块引用；DLL 是否立即卸载仍由 Windows 和模块自身的引用状态决定。
